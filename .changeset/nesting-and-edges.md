Nested territories and edges (spec 2026-10-25, slice E). A territory can name a `parent` (two levels; a parent lists `members: []`, nodes belong to leaves; `parent` and `group` cannot be mixed): far views read as families, each a palette colour, and near views as the leaves, each a lighter or darker tint of its family's colour. `MapSpec.edges` (`MapEdge { source, target, weight?, reason? }`, undirected, validated) draws lines and neighbour rings for the hovered and the selected item, up to `tuning.edgesPerNode` heaviest first; off-screen neighbours of the selected item are marked at the box edge and pressing a marker goes to it; the accessible tree lists and announces the selected item's related items at mid and near. New exports: `MapEdge`, `RelatedItem`, `relatedItems(spec, id)`. New handle method `CorpusMapHandle.reveal(id)` centres an item at the current zoom without selecting it. Type changes a consumer may need to follow: `Theme` gains a required `edge` colour (a theme built by spreading `DEFAULT_THEME` or `DARK_THEME` already has it; a theme written out field by field must add it), `Tuning` gains `edgesPerNode`, and code that implements `CorpusMapHandle` itself (a test double, say) must add `reveal`.
