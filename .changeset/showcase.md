---
"corpus-map": minor
---

`width` and `height` are now optional. Without them, `CorpusMap` measures its parent with a `ResizeObserver` (through an internal hook) and renders nothing until the first measurement; with both given, the map still fits to them immediately, with no observer. A box with zero width or height, from either source, counts as no box yet: the map paints nothing and fits to the first box whose sides are both positive. Either way, a later box change — from a new measurement, or from a later `width`/`height` prop change — keeps the current scale and keeps the world point that was at the old box's centre at the new box's centre, instead of refitting and discarding the user's zoom; a new `spec` still refits, as before. If you want to refit after a box change, pass a `ref` (typed `CorpusMapHandle`) and call its `fit()` — the same `ref` also exposes `zoomIn()`/`zoomOut()`, and a new `onViewChange` prop reports the regime, the scale ratio to the fitted scale, and the on-screen node count: once on mount, after any commit that changes one of those three values, and after every refit (a new `spec`, or `fit()`) even when they match. A new `minimap` prop (`boolean | { corner: "top-left" | "top-right" | "bottom-left" | "bottom-right" }`, default off) adds a 160 x 110 canvas in a corner of the box showing the territory shapes and the current view; pressing or dragging it centres the main view on the pressed world point, through the same coalesced `onViewChange`-firing update a drag on the map itself uses.

`resolveTuning` and `resolveThresholds` are now exported from the package's own public door (they were already reachable as internal declarations, but never through `src/index.ts`). Both validate and default their input the same way `CorpusMap` already does internally, throwing a `RangeError` naming the offending field on an invalid value — useful for a consumer that wants to validate a `tuning`/`thresholds` value before handing it to `CorpusMap`, the way the demo's new hidden tuning panel does.

A territory name wider or taller than the map's box is no longer drawn, since it could never be read whole there (on a phone-width box, the longest names wait for a larger one). Where a name sits never enters that decision, so a name that fits still slides off the edge clipped on pan and zoom instead of popping out.

A zoom step (wheel, pinch, `zoomIn()`, `zoomOut()`) never moves opposite to its direction: when a keep-view resize has left the scale outside the zoom band (zoomed all the way in, then the box shrinks), zooming in leaves the scale where it is instead of snapping out to the band edge.
