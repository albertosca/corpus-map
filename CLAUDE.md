# corpus-map — working notes

- Structure: feature folders under `src/` (`viewport/`, `lod/`, `territories/`, `points/`, `labels/`, `cards/`, `a11y/`, `minimap/`, `shared/`), tests colocated next to their code, `CorpusMap.tsx` orchestrates, `index.ts` is the only public door. See `ARCHITECTURE.md` for the full map, the pure/React boundary rule, paint order and how to add a feature.
- `npm test` — Vitest with an enforced, canaried coverage gate (lines 90 / branches 85); excludes `bench/**`, `**/.claude/**` and `**/.superpowers/**` on purpose (Vitest does not honour `.gitignore`: a worktree under `.claude/` would run the suite twice, and review probes left in the ignored `.superpowers/` workspace would run as tests). `testTimeout` is 15 s on purpose: heavy painted sweeps failed 5 s under load.
- `npm run bench` — the painter benchmark under its own `vitest.bench.config.ts`, against 10,000 items from `fixtures/synthetic/generate.ts` (a seeded generator, outside `src/` so it never ships); CI runs it as a separate job so the badge is real. Budget 16 ms is a stated target; the measured median runs roughly 1-4 ms locally (2026-09-24), depending on machine load.
- `npm run lint` — Biome, then `eslint --max-warnings 0 .` (`npm run format` applies Biome's formatting in place); ESLint carries only `eslint-plugin-react-hooks` plus the pure/React boundary rule, parsed through Babel (`@babel/eslint-parser`) because TypeScript 7 has no JS compiler API for `typescript-eslint` to use, and that Babel parser's ceiling is ESLint 9 (pinned).
- `npx tsc --noEmit`, `npm run build` — the build must leave `dist/index.d.ts`; CI asserts the file exists (`tsconfig.build.json` scopes emit to `src`; the root tsconfig would emit `dist/src/…`). `tsconfig.build.json` also excludes `src/**/*.test.{ts,tsx}` so colocated tests never ship.
- `npm run api:check` / `npm run api:update` — diffs (or rewrites) `api/corpus-map.api.d.ts`, the committed snapshot of every `dist/**/*.d.ts` concatenated in sorted order; CI runs `api:check` after the build, so any public type change must be accepted with `api:update` and reviewed in the diff.
- `npm run size` / `npm run size:badge` — gzips `dist/corpus-map.js` against the `sizeLimit.maximumGzipBytes` ceiling in `package.json` (and `dist/search.js` against `sizeLimit.search.maximumGzipBytes`; the badge is the main entry's) and checks (or rewrites) `docs/badges/size.svg` byte-for-byte; known open risk, CI Node 22's zlib gives a few bytes more than local Node's for the same file, check with `fnm exec --using=22 ...` since `npx -y node@22` silently runs the system Node here.
- `npx changeset` — records a changeset for `@changesets/cli`; run for any change a consumer would notice.
- `npm run dev` / `npm run build:demo` — the demo through `vite.demo.config.ts`, alias `corpus-map` → `src/index.ts`; the gallery ships arXiv (real-world, default, loaded lazily), elements, constellations and a synthetic corpus, never food. Each gallery entry carries its own `display` (slice G): `nearAt` from metric 18 (`demo/corpora/nearAt.test.ts`, measuring with `demo/corpora/labelledShare.ts`, fails when an entry's value or the library default drifts from what the measure picks), the selected card's size from `demo/cards.tsx`'s `cardSizeOf` (the renderers and the text they show live together there, so a renderer change must change `CARD_TEXT` with it); the tuning panel keeps edits per corpus and Copy settings yields the entry's `display` shape.
- `shared/scene.ts`'s `buildScene` computes territory shapes, placed names, territory `colours`, the fill `paintOrder`, the territory `groups` (declared or derived), their `groupLabels` and the scene `bounds` once per spec (memoized on primitives, not on the `tuning`/`theme` objects; the palette enters the memo as one joined string); `paint.ts` reads that `Scene` plus a per-frame `Frame` (regime, point fade, canvas size: a name wider or taller than the canvas is skipped; position never enters that decision, so names do not pop on pan or zoom) instead of recomputing shapes and label layout every frame. A `PlacedLabel`'s `activeFromScale` is an absolute viewport scale, not a ratio of `fitScale`, so a box resize alone never invalidates the scene.
- Time slicing (mobile spec §7, TBT): `buildingScene` and `placingItemLabels` are generators (`shared/steps.ts`: one `yield` per step, `finish` runs one to the end); `shared/useSliced.ts`'s `startSlices` runs the first slice inside the `useMemo` (step count only, so finishing in render never depends on the machine) and `useSliced` chains `setTimeout(0)` slices, each ending at its step count (`SCENE_STEPS_PER_SLICE` 32, `ITEM_LABEL_STEPS_PER_SLICE` 100) or at `SLICE_BUDGET_MILLISECONDS` (16), whichever comes first; a step yields before its work, so the budget is checked before a costly step starts. The demo's arXiv load expands and validates in two tasks (`demo/corpora/index.ts`'s `nextTask`), and `edges/related.ts` indexes edges and ids once per spec object (`WeakMap`), shared by the scene and `relatedItems`, so a selection does not walk every edge. A new spec draws nothing until its scene is built (`ready` waits for it, and the fit runs then; `EMPTY_SCENE` meanwhile); a tuning change on the same spec keeps the old scene until the new one is done. Small corpora finish in the first slice, so they still build in render; tests on a large corpus need fake timers or `waitFor` (`CorpusMap.sliced.test.tsx`).
- Dimming (`hiddenTerritories`) is per frame (`Frame.dimmed`), never in the scene; `liveSpec` (nodes of dimmed territories removed) feeds cards, the accessible tree, hover and `visibleCount`, while paint gets the full spec. The legend is `memo`'d and `CorpusMap.legendCommits.test.tsx` pins that a pan which keeps the on-screen set does not re-render it. The territory tooltip moves imperatively (`placeTooltip`) while the ids under the cursor stay the same, so a steady hover costs no commit; a touch tap names what it hits, and a touch `pointerleave` never closes it.
- Families (slice E): a `Territory.parent` makes two levels (a parent lists no members; nodes belong to leaves; the demo's elements and arXiv corpora declare parents, `demo/corpora/elements.test.ts` and `demo/corpora/arxiv.test.ts`); `buildScene` adds `groupShapes`/`groupBounds`/`groupColours` (a family's palette colour, each child an OKLab tint of it in `territories/tint.ts`), and `paintTerritories` cross-fades the leaves' and the families' fill layers by `Frame.groupAlpha`. A spec without groups leaves those maps empty and issues exactly the draw calls it issued before families existed (`paint.order.test.ts` pins this); metric 15 and 16 over every family tint live in `theme.metrics.test.ts`.
- Family focus (spec `2026-11-04-family-focus-design.md`): `Frame.focus` (family id → weight, never in the `Scene`) comes from `familyFocus(counts, tuning)` over the on-screen items of one `visibleNodes` call shared with `visibleCount`, memoized as a JSON key so a pan that moves no weight does not repaint; `levelsOf(groupAlpha, weight)` gives a family's leaf and family levels (bit-identical to before at weight 1), `paintTerritories` batches fills by distinct level, and `paintLabels` fades a family name below weight 1 by the highest drawn leaf name that boxes it. Defaults `focusFloor` 0.5 / `focusFull` 1 were measured, not guessed: 0.25/0.6 left 4 families at weight 1 (metric 19, `demo/corpora/familyFocus.test.ts`, also the continuity sweep and the family-name overlap pin). Whole-branch review fixes: the weight blends toward 1 while the largest on-screen count is under `FOCUS_CONFIDENT_ITEMS` (24), so a sparse screen keeps every family drawn; hover and the open territory follow what is painted (`namesLeaf`); a family name also gives way to a drawn item-label plate at near (`LabelBox.itemPlates`), and every such fade is graded over `OVERLAP_BAND` (8 px) so a zoom across the edge never pops it; the family fill layer is composited at `fillAlpha * level / (1 - fillAlpha * (1 - level))` so a leaf and its family together stay as opaque as at rest.
- Edges (slice E): `MapSpec.edges` are undirected; `Scene.related` holds both directions heaviest first, ties by id through the one shared `shared/compareIds.ts`. Lines and neighbour rings paint inside the point layer for the hovered and the selected item (`Tuning.edgesPerNode`, `Theme.edge`); off-screen neighbours get DOM markers above the cards (`edges/EdgeMarkers.tsx`, `aria-hidden`, pointer-transparent), resolved by the surface hit-test (`markerAt`) and moved to with `CorpusMapHandle.reveal`. The `insets` prop (`shared/insets.ts`) is the box area a consumer overlay covers: markers stay out of it and `reveal` centres in the rest, the fit ignores it on purpose (the ratio and regime must not move when a drawer opens); the demo passes the drawer's width. The demo's arXiv payload ships compact edges (`[source index, target index, weight × 100]`), expanded by `demo/corpora/edges.ts`'s `withExpandedEdges` (inside `compact.ts`'s `withExpandedArxiv`, which also rebuilds territory members and node `meta`, the arXiv category included) before `validateSpec`; any test reading `arxiv.json` directly goes through `arxivSpec` (`demo/corpora/index.ts`).
- Item labels (spec `2026-10-30-item-labels-design.md`): placed once per spec by `labels/itemLabels.ts`'s `placeItemLabels` (grid search through `labels/placeBoxes.ts`, exact against all pairs, seeded with the leaf names so a label never covers a name), memoized in `CorpusMap` outside `buildScene`, with the seeds compared by value (`labels/sameLabels.ts`, held in `useState`, so a palette change does not place them again); painted inside the point layer at near only, at `Frame.itemLabelAlpha`, and never skipped by position, so none pops on pan. Only the selected item gets a card (`cards/placeSelectedCard.ts`, the spot hiding the fewest drawn edges and points, a leader line for a far spot); a press on a drawn label selects its item (`labels/itemLabelAt.ts`).
- Arrows walk between spatial neighbours while an item is selected (spec `2026-11-01-spatial-keys-design.md`): `a11y/spatialNeighbour.ts` picks (and `nearestTo` starts the walk on Enter/Space), `viewport/follow.ts` keeps it in sight inside the usable area, announcements alternate a trailing no-break space so a repeat is spoken, and a move starts from the latest selection request while the drawn selection is still the one it was made over (a controlled consumer may commit late). `demo/corpora/arxiv.test.ts` sweeps the walk on the real corpus.
- Mobile (spec `2026-11-01-mobile-design.md`): touch goes through the pure recogniser `viewport/gestures.ts` (time from the event, so tests drive it without fake timers); the library's width rule is `NARROW_BOX_WIDTH` (600, the map's box: compact family names in `Scene.compactGroupLabels`, the legend's 44 px `touchTargets`), the demo's is `NARROW_WINDOW_WIDTH` (600, the window, `demo/components/narrow.ts`): Menu in a one-row top bar, no minimap, a 44 px Fit only, indicator and credit in one `data-bottom-strip`, drawer and tuning panel as sheets (`data-sheet-state`), `insets.bottom` = the collapsed sheet height even while expanded. `demo/App.test.tsx`'s floating-box sweep models the sheet and the strip from those attributes, so a new narrow control needs its box there too. The short-names guard rejects `MAX`/`MIN` inside constant names (`FOOTER_MAXIMUM_WIDTH`, not `FOOTER_MAX_WIDTH`).
- Search (spec `2026-11-02-search-design.md`): `matches` on `CorpusMap` (a set, a list, `null`/`undefined` for no search, an empty set dims everything) is dimmed per frame (`Frame.matches`, composing with `hiddenTerritories`), never in the scene; `CorpusMapHandle.revealAll(ids)` fits the live matches inside `insets` (`viewport/fitIds.ts`). `corpus-map/search` (`src/search/`, `SearchBox` and the local accent-folding `localSearch`) is its own Vite build (`vite.search.config.ts`, `emptyOutDir: false`, react external) behind the `./search` export, with its own gzip ceiling (`sizeLimit.search`); the `corpus-map/search` alias is a regex entry placed first in the three Vite/Vitest configs, since a string alias would also catch `corpus-map`. The native `<search>` element has no role in Testing Library: query it by tag and `aria-label`. The demo's TopBar owns the box and `App` owns `matches` (cleared on a corpus change). Ranked results (spec `2026-11-06-search-ranking-design.md`): `src/search/rank.ts` is the pure ordering (`orderLocal`, `orderAnswer`; facts cached per spec in a `WeakMap`; a plain id answer keeps its order, `{id, score}` sorts by score, a mixed answer throws and shows "Search failed"), `SearchBox` lists the first `SEARCH_RESULTS_VISIBLE` (50) as a `combobox` popover and calls `onGo` only on Enter or a click, never while typing; the demo's `handleGoToResult` zooms to `nearAt * 1.25` before `reveal`. The ceiling is `sizeLimit.search` 4110.
- Assistant (spec `2026-11-03-assistant-design.md`): `corpus-map/assistant` (`src/assistant/`, `AssistantBox`) is the third Vite build (`vite.assistant.config.ts`, `emptyOutDir: false`, react external) behind the `./assistant` export, with `sizeLimit.assistant`; the `corpus-map/assistant` regex alias (`^corpus-map\/assistant$`) sits first in the demo, vitest and bench configs beside the search one. The consumer's AI is an async `ask(request, signal)` adapter returning a whole `{text, ids}` (no streaming); the box highlights the cited ids through `onMatches`, frames them once with `onReveal` only when the `view` prop still equals the one captured at ask time, and offers Back through `onRestore`. `CorpusMapHandle.setView(view)` jumps to a public `MapViewport` and `getView()` reads the current one (the first fit is never reported by `onViewportChange`, so the demo seeds its view from `getView()`). The demo's `AssistantPanel` answers with `demo/assistant/standIn.ts` over the local search, behind a visible not-an-AI notice, collapsed until "Ask AI" is pressed; on narrow it takes turns with the item sheet (both are layout-swept in `demo/App.test.tsx`).
- Filter (spec `2026-11-03-filter-design.md`): `corpus-map/filter` (`src/filter/`, `FilterBox`) is the fourth Vite build (`vite.filter.config.ts`, `emptyOutDir: false`, react external) behind the `./filter` export, with `sizeLimit.filter`; the `corpus-map/filter` regex alias sits first in the demo, vitest and bench configs beside the other two, and `scripts/size.mjs` loops over all three opt-in builds. The consumer's `attribute(node)` returns a value, a list or `{value, label}`; the box reports ids through `onMatches` (`null` while nothing is selected, never an empty list: an empty `matches` dims everything). The demo keeps `searchMatches` (search and assistant) and `filterMatches` apart and gives the map `intersectMatches` of the two (`null` = no constraint); a gallery entry declares its `filter` (arXiv: `meta.category` through `demo/corpora/arxivFilter.ts`), and the narrow bar puts the Filter first in the Menu popover. `demo/App.test.tsx`'s filter tests scope `isMatch` to the map, since the dialogue shows same-named item buttons. `api/**` turns Biome's assist off (the snapshot is generated).
- `CorpusMap` fills its parent (`useElementSize`, a `ResizeObserver` hook) when `width`/`height` are omitted; any box change after the first — props or measurement — keeps the current scale and centre instead of refitting, only a new `spec` refits. A `ref` (`CorpusMapHandle`: `zoomIn`/`zoomOut`/`fit`) and `onViewChange` (`{ regime, ratio, visibleCount }`, fired on mount, after a commit that changes one of those values, and after every refit even when they match) are exported, plus an optional `minimap` prop (`src/minimap/`) that mirrors the current view in a corner canvas.
- `viewport`/`selectedId` are controlled like `hiddenTerritories`: every view change goes through `requestViewport` (one gate: stores or proposes, emits once per real change, composes updaters until the next commit); a new spec in controlled mode proposes its fit (`reason: "spec"`) and resets the regime only when the consumer draws that fit; `publicViewport.ts` holds the pure conversion. The selection ring is painted inside the point layer (`points/paintSelection.ts`), and `onOpenTerritoryChange` is derived per render at near, deduped on the value.
- `Surface.layer` draws into an offscreen canvas cached per context (`WeakMap`); under jsdom (no `getContext`) the fallback path draws straight onto the target, so overlap behaviour is only visible in a browser.
- Demo layout tests (`demo/App.test.tsx`) read inline styles only (jsdom has no layout): every `data-floating-control` must be `position: fixed/absolute` with a `width`/`maxWidth` and a `left`/`right`, and every button/select inside needs its own `maxWidth` — a container's `maxWidth` does not bound its children. Real-browser layout is `docs/superpowers/REVIEW-RUNBOOK.md` B9.
- Test fakes: a `ResizeObserver` fake must report the current size on `observe()` like the real one; an rAF mock that runs the callback immediately breaks two coalesced flushes in one component — queue, then flush inside `act()`.
- `demo/corpora/arxiv.test.ts` runs spec 4's acceptance 2 and a pan/zoom pop sweep on the real corpus; any change to label placement or painting must keep it and metric 7 green on the real canvas size.
- The map-feel metrics (spec `2026-09-23-map-feel-design.md`, section 7) are not a separate suite: each is a colocated test tagged `metric N` in its `it`/`describe` name — grep `"metric "` under `src/` and `demo/` to find all 18. Metric 18 (`demo/corpora/nearAt.test.ts`, slice G) picks `DEFAULT_THRESHOLDS.nearAt` and each gallery entry's `nearAt` from the labelled share of item labels (`demo/corpora/labelledShare.ts`); a change to item-label placement or wrapping, the fit, or a corpus can move the answer and turns it red.
- Gotchas: `@types/react` 19 has no global `JSX` (return `ReactElement`); TypeScript 7 has no `baseUrl` (`paths` only); Testing Library cleanup and the jsdom `getContext` stub live in `test/setup.ts` (no `globals: true`); the card overlay is `inert`, so cards cannot own click handlers — selection is a hit-test on the surface; wheel zoom is a native non-passive listener, never React `onWheel`.
- Docs: `ARCHITECTURE.md` at the repo root; specs in `docs/superpowers/specs/`, living plans (every deviation noted) in `docs/superpowers/plans/`, `docs/superpowers/BACKLOG.md`, `docs/superpowers/GOING-PUBLIC.md`, `docs/superpowers/REVIEW-RUNBOOK.md` (the owner's browser review), `docs/coverage-badge.md`.
- `pipeline/arxiv/` builds the arXiv cs corpus the demo ships (`demo/corpora/arxiv.json`/`arxiv.meta.json`) -- a separate Python package (uv-managed); stages `fetch → embed → project → edges → cluster → name → check → export`, where the territories are Ward clusters of the 2D map (18-26 leaves under 5-9 declared families) named by Claude and gated by a blind test, each paper's arXiv category kept as `meta.category`; `name`/`check` run `claude -p` on the subscription by default (`ARXIV_NAMING_BACKEND=api` for the SDK with the `naming` extra); its own gates as CI actually runs them (`cd pipeline/arxiv && uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src tests`, `uv run pytest`), run once locally against the live arXiv API; the output is committed, not regenerated in CI. See `pipeline/arxiv/README.md`.
- `tools/group-names/` (slice F) names a corpus's derived groups with Claude, offline: `set -a; source ~/.config/anthropic/api.env; set +a; bun tools/group-names/main.ts <corpus.json> <names.json>` (costs cents; review the names in the diff, a name that misdescribes its group is a re-run, not a hand edit). Outside `src/`, never shipped; `@anthropic-ai/sdk` is a devDependency. `main.ts` declares `process` and loads `node:fs/promises` through a variable specifier because the package has no `@types/node` on purpose (node types would leak into the browser library). The SDK refuses jsdom, so its tests carry `// @vitest-environment node`. No gallery corpus uses it any more: arXiv declares its families from the pipeline.
