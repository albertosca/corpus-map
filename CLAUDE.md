# corpus-map — working notes

- Structure: feature folders under `src/` (`viewport/`, `lod/`, `territories/`, `points/`, `labels/`, `cards/`, `a11y/`, `minimap/`, `shared/`), tests colocated next to their code, `CorpusMap.tsx` orchestrates, `index.ts` is the only public door. See `ARCHITECTURE.md` for the full map, the pure/React boundary rule, paint order and how to add a feature.
- `npm test` — Vitest with an enforced, canaried coverage gate (lines 90 / branches 85); excludes `bench/**` and `**/.claude/**` on purpose (Vitest does not honour `.gitignore`, and a worktree under `.claude/` would run the suite twice).
- `npm run bench` — the painter benchmark under its own `vitest.bench.config.ts`, against 10,000 items from `fixtures/synthetic/generate.ts` (a seeded generator, outside `src/` so it never ships); CI runs it as a separate job so the badge is real. Budget 16 ms is a stated target; the measured median runs roughly 4-9 ms locally, depending on machine load.
- `npm run lint` — Biome, then `eslint --max-warnings 0 .`; ESLint carries only `eslint-plugin-react-hooks` plus the pure/React boundary rule, parsed through Babel (`@babel/eslint-parser`) because TypeScript 7 has no JS compiler API for `typescript-eslint` to use, and that Babel parser's ceiling is ESLint 9 (pinned).
- `npx tsc --noEmit`, `npm run build` — the build must leave `dist/index.d.ts`; CI asserts the file exists (`tsconfig.build.json` scopes emit to `src`; the root tsconfig would emit `dist/src/…`). `tsconfig.build.json` also excludes `src/**/*.test.{ts,tsx}` so colocated tests never ship.
- `npm run api:check` / `npm run api:update` — diffs (or rewrites) `api/corpus-map.api.d.ts`, the committed snapshot of every `dist/**/*.d.ts` concatenated in sorted order; CI runs `api:check` after the build, so any public type change must be accepted with `api:update` and reviewed in the diff.
- `npm run size` / `npm run size:badge` — gzips `dist/corpus-map.js` against the `sizeLimit.maxGzipBytes` ceiling in `package.json` and checks (or rewrites) `docs/badges/size.svg` byte-for-byte; known open risk, CI Node 22's zlib gives a few bytes more than local Node's for the same file, check with `fnm exec --using=22 ...` since `npx -y node@22` silently runs the system Node here.
- `npx changeset` — records a changeset for `@changesets/cli`; run for any change a consumer would notice.
- `npm run dev` / `npm run build:demo` — the demo through `vite.demo.config.ts`, alias `corpus-map` → `src/index.ts`; the gallery ships arXiv (real-world, default, loaded lazily), elements, constellations and a synthetic corpus, never food.
- `shared/scene.ts`'s `buildScene` computes territory shapes and placed names once per spec (memoized on primitives, not on the `tuning`/`theme` objects); `paint.ts` reads that `Scene` plus a per-frame `Frame` (regime, point fade) instead of recomputing shapes and label layout every frame. A `PlacedLabel`'s `activeFromScale` is an absolute viewport scale, not a ratio of `fitScale`, so a box resize alone never invalidates the scene.
- `CorpusMap` fills its parent (`useElementSize`, a `ResizeObserver` hook) when `width`/`height` are omitted; any box change after the first — props or measurement — keeps the current scale and centre instead of refitting, only a new `spec` refits. A `ref` (`CorpusMapHandle`: `zoomIn`/`zoomOut`/`fit`) and `onViewChange` (`{ regime, ratio, visibleCount }`, once per commit) are exported, plus an optional `minimap` prop (`src/minimap/`) that mirrors the current view in a corner canvas.
- The map-feel metrics (spec `2026-09-23-map-feel-design.md`, section 7) are not a separate suite: each is a colocated test tagged `metric N` in its `it`/`describe` name — grep `"metric "` under `src/` to find all 14.
- Gotchas: `@types/react` 19 has no global `JSX` (return `ReactElement`); TypeScript 7 has no `baseUrl` (`paths` only); Testing Library cleanup and the jsdom `getContext` stub live in `test/setup.ts` (no `globals: true`); the card overlay is `inert`, so cards cannot own click handlers — selection is a hit-test on the surface; wheel zoom is a native non-passive listener, never React `onWheel`.
- Docs: `ARCHITECTURE.md` at the repo root; spec in `docs/superpowers/specs/`, the living plan with every deviation noted, `BACKLOG.md` (label decluttering at the far regime comes first), `GOING-PUBLIC.md`, `docs/coverage-badge.md`.
- `pipeline/arxiv/` builds the arXiv cs corpus the demo ships (`demo/corpora/arxiv.json`/`arxiv.meta.json`) -- a separate Python package (uv-managed), its own gates as CI actually runs them (`cd pipeline/arxiv && uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src tests`, `uv run pytest`), run once locally against the live arXiv API; the output is committed, not regenerated in CI. See `pipeline/arxiv/README.md`.
